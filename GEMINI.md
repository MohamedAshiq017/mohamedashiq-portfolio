# Project Instructions

## Development Workflow
- **Commit Policy:** Every functional change or bug fix must be committed to git immediately after verification.
- **Commit Messages:** Commit messages must be concise, follow conventional commit format (e.g., `feat: ...`, `fix: ...`, `chore: ...`), and focus on the 'why' of the change.

## Shared Agent Rules
- Read the relevant files before editing and keep changes narrowly scoped to the request.
- Preserve unrelated user changes; never reset, checkout, or overwrite them.
- Run the narrowest useful validation after each functional edit, then commit verified changes.
- Keep portfolio content in `src/config.js`; do not change it for visual-only work.
- Prefer existing project patterns and avoid unnecessary dependencies or refactors.
